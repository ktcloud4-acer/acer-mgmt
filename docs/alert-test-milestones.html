Acer 알림 테스트 마일스톤

운영 장애를 만들지 않고 Slack 알림 경로를 확인하기 위한 체크리스트입니다. 체크하면 항목이 흐려지고, 진행 상태는 브라우저에 저장됩니다.

#git-알림 GitLab Slack integration

push, MR, pipeline 이벤트 알림입니다. 본문 템플릿은 GitLab 내장 형식이라 제한적이고, 표시 이름은 한글로 정리했습니다.

#argocd-알림 ArgoCD notification webhook

배포 실패/장애, 배포 완료/복구를 한글 메시지로 보냅니다.

#infra-알림 Grafana Alerting

mgmt, aio, 각 클러스터, OpenCost, node-exporter, kubelet/cAdvisor 상태를 보냅니다.

0. 사전 확인

Webhook 값이 Git에 들어가지 않았는지 확인

실제 URL은 서버 .env 또는 Kubernetes Secret에만 있어야 합니다.

cd ~/acer-mgmt
grep -R "hooks.slack.com/services" . --exclude-dir=.git || true

Grafana 알림 설정 상태 확인

docker inspect grafana --format '{{range .Config.Env}}{{println .}}{{end}}' \
  | grep '^SLACK_WEBHOOK_INFRA=' \
  | sed 's/=.*$/=<set>/'

docker exec grafana sh -lc \
  'curl -fsS -u "$GF_SECURITY_ADMIN_USER:$GF_SECURITY_ADMIN_PASSWORD" \
  http://127.0.0.1:3000/api/v1/provisioning/alert-rules' \
  | python3 -m json.tool | head -80

ArgoCD 알림 Secret/ConfigMap 확인

kubectl -n argocd get secret argocd-notifications-secret -o jsonpath='{.data.argocd-slack-webhook-url}' \
  | wc -c

kubectl -n argocd get cm argocd-notifications-cm -o yaml \
  | grep -E "배포 실패|배포 완료|trigger.on-"

1. 안전 테스트: Slack 경로만 확인

실제 장애를 만들지 않고 각 webhook이 Slack 채널로 메시지를 보낼 수 있는지 확인합니다.

#infra-알림 직접 전송 테스트

cd ~/acer-mgmt
. ./.env
curl -sS -X POST -H 'Content-type: application/json' \
  --data '{"text":"[테스트] #infra-알림 경로 확인\n대상: Grafana infra alert webhook\n결과: 이 메시지가 보이면 Slack 경로는 정상입니다."}' \
  "$SLACK_WEBHOOK_INFRA"

#argocd-알림 직접 전송 테스트

ARGOCD_HOOK="$(kubectl -n argocd get secret argocd-notifications-secret \
  -o jsonpath='{.data.argocd-slack-webhook-url}' | base64 -d)"

curl -sS -X POST -H 'Content-type: application/json' \
  --data '{"text":"[테스트] #argocd-알림 경로 확인\n대상: ArgoCD notification webhook\n결과: 이 메시지가 보이면 Slack 경로는 정상입니다."}' \
  "$ARGOCD_HOOK"

2. 실제 파이프라인 테스트: 알림 엔진까지 확인

임시 테스트 리소스를 만들고 바로 제거합니다. 운영 워크로드를 건드리지 않습니다.

Grafana Alerting 임시 firing 테스트

임시 rule을 만들기 때문에 #infra-알림에 테스트 firing 메시지가 1회 갈 수 있습니다.

cd ~/acer-mgmt
cat > compose/stacks/observability/grafana/provisioning/alerting/zz-test-infra-alert.yaml <<'YAML'
apiVersion: 1
groups:
  - orgId: 1
    name: infra-smoke-test
    folder: Infra Alerts
    interval: 10s
    rules:
      - uid: infra_smoke_test
        title: "[테스트] Grafana infra 알림 경로 확인"
        condition: A
        data:
          - refId: A
            datasourceUid: "__expr__"
            model:
              datasource: { type: __expr__, uid: "__expr__" }
              expression: "1"
              intervalMs: 1000
              maxDataPoints: 43200
              refId: A
              type: math
              conditions:
                - evaluator: { params: [0], type: gt }
                  operator: { type: and }
                  query: { params: [A] }
                  reducer: { params: [], type: last }
                  type: query
        noDataState: OK
        executionErrorState: Error
        for: 10s
        annotations:
          summary: "Grafana infra 알림 테스트입니다."
          description: "테스트 완료 후 이 rule은 삭제해야 합니다."
        labels:
          severity: test
          team: monitoring
          channel: infra
          scope: test
          cluster: test
        notification_settings:
          receiver: slack-infra-alerts
          group_by: [alertname, grafana_folder, severity, scope, cluster]
          group_wait: 5s
          group_interval: 1m
          repeat_interval: 1h
YAML

docker compose --env-file .env -f compose/stacks/observability/grafana/compose.yaml up -d
sleep 40
docker exec grafana sh -lc 'curl -fsS -u "$GF_SECURITY_ADMIN_USER:$GF_SECURITY_ADMIN_PASSWORD" http://127.0.0.1:3000/api/prometheus/grafana/api/v1/rules' \
  | grep -A4 "infra_smoke_test" || true

rm -f compose/stacks/observability/grafana/provisioning/alerting/zz-test-infra-alert.yaml
docker compose --env-file .env -f compose/stacks/observability/grafana/compose.yaml up -d

ArgoCD notification 임시 Application 테스트

운영 앱이 아닌 임시 Application을 만들고 삭제합니다. #argocd-알림에 실패/장애 테스트 메시지가 갈 수 있습니다.

cat <<'YAML' | kubectl apply -f -
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: alert-smoke-test
  namespace: argocd
  annotations:
    notifications.argoproj.io/subscribe.on-failure.argocd_slack: ""
spec:
  project: default
  source:
    repoURL: https://gitlab.imcherry5778.xyz/acer-group/does-not-exist.git
    targetRevision: main
    path: not-found
  destination:
    server: https://kubernetes.default.svc
    namespace: alert-smoke-test
YAML

sleep 90
kubectl -n argocd get application alert-smoke-test -o wide
kubectl -n argocd logs deploy/argocd-notifications-controller --since=2m | tail -80
kubectl -n argocd delete application alert-smoke-test

3. GitLab 알림 테스트

GitLab Slack integration은 GitLab 이벤트가 실제로 발생해야 완전한 테스트가 됩니다. 기본 브랜치 push 알림을 켜 둔 상태라 main에 테스트 커밋이 남을 수 있습니다.

표시 이름/채널 설정 확인

sudo docker exec gitlab gitlab-rails runner /tmp/list_gitlab_slack_names.rb

실제 #git-알림 이벤트 테스트

이 단계는 main 브랜치에 테스트 커밋이 남습니다. 팀 합의 후에만 실행하세요.

cd ~/acer-mgmt
printf "\n- %s #git-알림 테스트\n" "$(date -Iseconds)" >> docs/git-alert-smoke-test.md
git add docs/git-alert-smoke-test.md
git commit -m "test: trigger git slack notification"
git push
